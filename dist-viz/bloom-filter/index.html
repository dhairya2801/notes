What is a Bloom Filter?

A Bloom filter is a compact data structure that answers "is this element in the set?" It can say "definitely not" or "probably yes" — but never gives a false negative. It uses a bit array plus multiple hash functions, trading a small false positive rate for extreme space efficiency.

How It Works

The filter is a bit array of m bits, all initially 0. To add an element, compute k independent hash functions, each producing a bit index (0 to m−1). Set all k bits to 1. To check membership, compute the same k hashes. If all k bits are 1, the element is "probably present." If any bit is 0, the element is definitely not in the set.

False Positives

As more elements are added, more bits become 1, and the chance increases that an element not in the set has all its k bits coincidentally set. The false positive probability is approximately: (1 − e^(−kn/m))^k, where n is the number of inserted elements. The optimal number of hash functions is k = (m/n) × ln(2).

Key Properties

No false negatives — if the filter says "no," the element was definitely never added.
No deletion — you can't remove elements (unsetting bits would break other elements). Counting Bloom filters address this.
Space efficient — much smaller than storing the actual set. With 1% FP rate, you need ~9.6 bits per element.

Real-World Uses (from DDIA)

Databases use Bloom filters to avoid unnecessary disk reads — LSM-tree storage engines (like LevelDB, RocksDB, Cassandra) check a Bloom filter before reading an SSTable, skipping the read entirely if the key is definitely absent. Also used in CDNs, spell checkers, and network routers.
